## 题目描述

附件是一张密文图片：9 行 × 15 列的怪符号网格。题目名"黄道十二宫"（平台上写作"黄道十二官"）。

## 解题过程

### 0x01 题目名即提示：先查案

"黄道十二宫"不是随口起的名字——它是密码学史上最著名的真实悬案：1969 年，美国连环杀手"黄道十二宫杀手"寄给媒体一封 **340 字符的密信**（Z340），FBI 与民间破译者斗了 **51 年**，直到 **2020 年 12 月**才被 Oranchak 团队用计算机攻破。

破译钥匙有两把：①密信虽按行书写，但要沿**对角线**阅读（下一行右移 2 格）；②斜读后是**替换密码**，靠统计工具破。BugKu 这题是它的 9×15 缩小版，两把钥匙原样保留。

**做 CTF 的新姿势：题目背景本身就是解题说明书。**

### 0x02 转写：把符号变成字符

把图片上每个符号转成文本字符（同类符号固定用同一字符，不同类用不同字符）。这步最枯燥也最要命——**转错一个，后面全崩**。实用技巧：

- 用图片查看器放大，一行一行数着敲
- 转完先自检：行 × 列 = 总字符数对不对（本题 9×15=135）
- 网上的转写版本可以对照，但别人的笔误比想象中常见，**以原图为准**

### 0x03 斜读重排：核心一步

规则：新文本第 1 个字符取第 1 行第 1 个，第 2 个取第 2 行第 3 个，第 3 个取第 3 行第 5 个……下一行右移 2 格，到头环绕。20 行 Python 搞定：

```python
def diagonal_rearrange(text, rows=9, cols=15, step=2):
    s = ''.join(text.split())
    n = rows * cols
    order, pos = [], 0
    for _ in range(n):
        order.append(pos)
        pos = (pos + cols + step) % n   # 下一行、右移 2 格
    out = ''.join(s[p] for p in order)
    return '\n'.join(out[i:i+cols] for i in range(0, len(out), cols))
```

斜读后得到的是**待破译的替换密文**（本题 25 种符号）。

### 0x04 AZdecrypt 一键破译

替换密码人肉解不动，上专用工具 [AZdecrypt](https://github.com/doranchak/azdecrypt)（Z340 破译团队同款）：

1. 下载 ZIP → **解压**（别在压缩包里预览）→ 根目录双击 `AZdecrypt 1.25 (x86-64)`
2. 斜读后的密文粘进 **Input window**
3. Solvers 保持 **Substitution** → 点 **Solve**
4. 爬山算法需要运气：**连续多次 Solve**，盯 Score——跳高 + 输出变成通顺英文即中

真解是通顺的英文短句，**最后两个单词小写、去空格**即 flag：flag{***}。

## 原理分析

### 这题的密码 = 转置 + 替换 两层套娃

- **第一层 转置**：斜读本质是**位置重排**——《散乱的密文》的老朋友，只是从"按组换位"升级成"沿对角线走"
- **第二层 替换**：斜读后每个符号对应一个字母——《抄错的字符》的亲戚，但映射表保密，且一符可能对多字母（同音替换，用于对抗频率分析）

真 Z340 用了 63 个符号写 340 字符（同音替换拉平频率）；本题 25 符号写 135 字符，接近一一同构，难度友好得多。

### 为什么斜读这么关键

1969-2020 年间，全世界的破译者都把 Z340 当**纯替换密码**暴力破解，51 年无果——因为密文还叠了一层转置，替换表再怎么猜也是错的。**复合密码必须按"后进先出"逐层剥**：先转置（斜读还原），再替换（统计破解）。这也是密码分析的经典教训：结构判断错了，算力再大也是白烧。

### 爬山算法与 250 万次重启

AZdecrypt 的求解策略是"爬山"：随机猜一张替换表 → 评估解出的文本像不像英语（N-gram 词频打分）→ 每次微调一个映射，分数变好就保留。问题是**局部最优**：半通顺的假解就像半山腰的凹地，算法蹲在里面出不来，只能随机重启再爬。Oranchak 团队当年跑了约 **250 万次**重启才命中 Z340 真解。所以"多按几次 Solve"不是笨办法，是这类题的标准姿势。

## 复盘

- 解题路径：查案件背景 → 转写（逐格核对）→ 斜读脚本 → AZdecrypt 反复 Solve → 语义锁定 flag
- **背景即考点**：真实事件改编的题，案件历史就是 writeup——遇到陌生题目名，第一反应搜它的现实原型
- **工具踩坑实录**（本篇的隐藏主线）：
  - ZIP 里双击进的是预览，**必须先解压**
  - AZdecrypt 根目录才是主程序，`Ciphers`/`Tests` 文件夹全是自带题库——进去两次才长记性
  - 追求"能跑就行"选基础版 exe（x86-64），加速版对 135 字符毫无意义
- **验证思维**：斜读脚本先拿自造消息闭环测试（PASS）再上真实数据；重排结果与网上 WP 前 8 字符吻合才放心
- 爬山不收敛的教训：短密文统计信号弱，Score 卡在局部最优很正常——重试 > 焦虑
- 知识链回顾：散乱的密文（换位置）→ 富强民主（换字符集）→ .!?（极简字符集）→ 抄错的字符（损毁重建）→ **黄道十二宫（转置+替换复合，真·密码）**——Crypto 从"识别编码"正式毕业到"破译密码"
