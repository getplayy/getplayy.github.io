## 题目描述

老师让小明抄写一段话，结果粗心的小明把部分数字抄成了字母，还因为强迫症把所有字母都换成大写。你能帮小明恢复并解开答案吗？

密文：`QWIHBLGZZXJSXZNVBZW`

## 解题过程

### 0x01 题面即规则书

这题最妙的地方：**题目描述本身就是还原规则**。小明的两个错误，反过来读就是两条还原指令：

| 小明的错 | 还原操作 |
|---|---|
| 数字抄成形近字母 | `I↔1`、`Z↔2`、`S↔5`、`B↔6`、`G↔9`、`O↔0` |
| 所有字母强制大写 | 大小写信息丢失，每个字母要试原大写 / 原小写 |

注意候选不是简单二选一：比如 `Z` 可能原样是 `Z`/`z`，也可能是数字 `2`——**三种可能**。

### 0x02 三板斧定位编码

老配方，编码三板斧：

- **数字符集**：19 个字符，纯大写字母——数字和小写字母集体失踪
- **看结构**：19 + 补 1 个 `=` = 20，正好 4 的倍数；而 Base64 的字符集恰好是"大写 + 小写 + 数字 + / +"，**缺失的部分全在题面里给了交代**
- **得出猜想**：原文是一段 Base64，先被数字→形近字母替换、再被整体大写化，两步破坏

### 0x03 分组还原：4:3 是关键

Base64 编码是**每 3 字节 → 4 字符**，反过来**每 4 字符独立解出 3 字节**，组与组互不影响——这就是突破口：不需要对 19 个字符整体枚举，**4 个一组分开试**，每组最多 3⁴ = 81 种组合：

| 密文组 | 还原 | 解码 |
|---|---|---|
| `QWIH` | `QW1h` | `Ama` |
| `BLGZ` | `bl92` | `n_v` |
| `ZXJS` | `ZXJ5` | `ery` |
| `XZNV` | `X2Nv` | `_co` |
| `BZW` | `b2w=` | `ol` |

每组能解出可打印字符的候选其实有 3~10 种，最后靠**语义通顺**筛出唯一解——五组拼起来是一句通顺的英文（出题人的自我评价），就是它了。

## 原理分析

### Base64：为什么 4 字符一组

Base64 用 **64 个字符**（`A-Z`、`a-z`、`0-9`、`+`、`/`）表示任意二进制：3 字节 = 24 bit，切成 4 段 × 6 bit，每段查表转成 1 个字符。所以 **4 个字符永远对应 3 个字节**，天然分组、互不干扰——不够 3 字节时用 `=` 补位（本题末组 3 字符 + 1 个 `=`）。

这个 4:3 对应正是本题可解的数学基础：把 19 字符的混沌枚举拆成 5 组各 ≤81 次的小枚举，计算量从**万级**掉到**百级**。

### 信息丢失后的"约束还原"三件套

小明的两步操作都是**有损破坏**（大小写信息、数字信息都丢了），无法完美逆推。但题目留了三层约束，层层收窄：

1. **映射约束**：形近字母表（`Z` 只能是 `Z/z/2`，不可能是 `7`）——把候选从 62 种压到 2~3 种；
2. **结构约束**：Base64 4:3 分组——组间解耦，可分治；
3. **语义约束**：解码结果必须是可打印、通顺的英文——从"有效解"里挑出"正确解"。

信息丢失不可怕，没有约束才可怕。CTF 里大量"还原类"题（被截断的密文、被污染的文件头）走的都是这条路。

### 人 + 工具分工

枚举交给脚本，语义判断留给人脑——各干擅长的事。20 行 Python 把每组的全部可打印候选列出来：

```python
import base64
from itertools import product

cipher = 'QWIHBLGZZXJSXZNVBZW'
LOOKALIKE = {'I': '1', 'L': '1', 'Z': '2', 'S': '5', 'B': '6', 'G': '9', 'O': '0'}

def candidates(ch):
    cands = [ch, ch.lower()]
    if LOOKALIKE.get(ch) and LOOKALIKE[ch] not in cands:
        cands.append(LOOKALIKE[ch])
    return cands

groups = [cipher[i:i+4] for i in range(0, len(cipher), 4)]
for g in groups:
    pad = '=' * ((4 - len(g)) % 4)
    for combo in product(*[candidates(c) for c in g]):
        s = ''.join(combo) + pad
        try:
            dec = base64.b64decode(s).decode('ascii')
            if dec and all(32 <= ord(c) < 127 for c in dec):
                print(f'{s:6s} -> {dec!r}')
        except Exception:
            pass
```

跑出来每组一小片候选，肉眼一扫语义即锁定——**这一幕和《散乱的密文》"先猜 flag{ 再倒推顺序"是同一个思想：让工具穷举，让线索收口**。

## 复盘

- 解题路径：读题提规则 → 三板斧猜 Base64 → 4 字符分组枚举 → 语义筛选 → 拼接提交，全程 10 分钟
- **三板斧升级**：第一步"数字符集"要加一条新认知——**字符集可能本身就被破坏过**。纯大写 19 字符乍看不像 Base64，但题面"抄错了"就是"字符集不可信"的明示，线索在题目里
- **分治思想**：大枚举拆成独立小枚举（4:3 分组），是 CTF 通用套路——后续 RSA 的分组、隐写的分通道还会反复遇到
- 踩坑记录：最后一组 `BZW` 只有 3 个字符，直接解码失败，**想起 Base64 的 `=` 补位**才通过——padding 不是装饰品，是格式的一部分
- 知识链回顾：滑稽（看源码）→ 计算器（改前端）→ alert（解编码）→ GET/POST（构造请求）→ 散乱的密文（换位置）→ 富强民主（换字符集）→ linux/Linux2（捞字符串）→ .!?（极简字符集）→ **抄错的字符（字符集损毁后重建）**——编码题第四种形态到齐，从"识别"进阶到"还原"
