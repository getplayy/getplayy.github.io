# 【Bugku CTF】你必须让他停下 Writeup

- **平台**：[Bugku CTF](https://ctf.bugku.com/)
- **分类**：WEB
- **分值**：10 分（入门）
- **考察点**：禁用 JS 绕过前端逻辑 + HTTP 请求重放 + 隐藏元素信息泄露

> 个人学习记录，flag 已打码，请自行做题获取。

## 题目描述

I want to play Dummy game with others! But I can't stop!（我想和别人玩Dummy游戏！但我停不下来！）
Stop at panda! u will get flag（停在熊猫那！你会拿到 flag）

## 解题过程

### 0x01 侦察页面

打开环境，页面上有一张图片和一句提示，然后——**页面每 0.5 秒自动刷新一次**，肉眼根本来不及看清内容，连 F12 都被频繁的重载打断。

冷静观察：刷新是由 JS 驱动的（源码中 `setTimeout('myrefresh()', 500)`），而**图片每次刷新都在变化**。

### 0x02 分析机制

从源码读出页面逻辑：

```html
<script language="JavaScript">
function myrefresh() {
    window.location.reload();
    setTimeout('myrefresh()', 500);
}
</script>
<body>
    <center>Stop at panda ! u will get flag</center>
    <center><div><img src="10.jpg"></div></center>
    <br><a style="display:none">flag{***}</a>
</body>
```

三个关键信息：

1. **刷新是前端 JS 干的**——服务器没有强制刷新，禁用 JS 就能停下
2. **提示"停在熊猫"**——服务器每次随机返回不同的图片，**只有返回熊猫图（如 10.jpg）的那次响应里才带 flag**
3. **flag 藏在 `display:none` 的 `<a>` 标签里**——即使在正确响应里，页面上也看不见，必须看源码

### 0x03 解法一：禁用 JS + 手动刷新（推荐，零工具）

1. F12 打开 DevTools
2. 按 `Ctrl + Shift + P` 打开命令菜单，输入 `禁用 JavaScript`（英文版输入 `Disable JavaScript`）→ 回车
3. 页面顶部出现黄色提示条"已停用 JavaScript"——**自动刷新停止了** ✅
4. 手动按 `F5` 刷新，观察每次的图片——**一直刷，直到出现熊猫图**
5. 命中后按 `Ctrl + U` 查看源码，`Ctrl + F` 搜 `flag`，找到隐藏 `<a>` 标签里的 flag

> 注意：JS 只在 DevTools 打开期间、当前标签页被禁用，关掉 DevTools 自动恢复，不影响正常上网。

### 0x04 解法二：Burp Repeater 重放

1. 浏览器配置 Burp 代理，打开题目页面，Burp 拦下请求
2. 右键请求 → **Send to Repeater**（或快捷键 `Ctrl + R`）
3. 切到 Repeater 标签，反复点 **Send** 发送
4. 每次响应里的图片 `src` 不同——**一直 Send，直到响应里搜到 `flag`**
5. Repeater 的优势：**不用等浏览器渲染**，直接在响应原文里 `Ctrl + F` 搜 flag，比肉眼看图快得多

```http
HTTP/1.1 200 OK
Content-Type: text/html

<html>
    ...
    <img src="10.jpg">
    <a style="display:none">flag{***}</a>
</html>
```

### 0x05 拿分

复制 flag 提交平台，+10 分。

## 原理分析

### 三层知识点

**1. 禁用 JS：客户端不可信的第三次应用**

自动刷新是**纯前端行为**（JS 的 `reload()`），服务器从不强制。禁用 JS = 砍掉客户端的一切主动行为，页面立刻"听话"。这与「计算器」改 `maxlength`、「POST」绕过页面直接构造请求一脉相承：**客户端代码是建议，不是约束**。

**2. 隐藏元素：信息泄露的老朋友**

`display:none` 的元素不渲染但存在于 DOM——与「滑稽」的 HTML 注释同属"页面看不到、源码里都有"的信息泄露家族。**识别清单再加一条**：注释、HTTP 响应头、隐藏 input、`display:none` 元素。

**3. 请求重放：HTTP 的无状态性**

HTTP 是无状态协议——服务器不记得"上次给你发过什么图"，每个请求独立随机出图。所以**同一 URL 重复请求 = 抽奖**，多试必中。Burp Repeater 就是为此而生：修改→发送→观察，秒级循环。这是后续「Web6 速度要快」（还要叠加脚本读响应头）和所有爆破题的基础功。

### 为什么这题设计成"停不下来"

出题人用 500ms 的强制刷新制造了两个障碍：①让你没法安静分析页面 ②让浏览器正常访问变成"抽卡"。破题思路是**把问题拆开**：刷新归 JS 管（禁掉它）、随机归服务器管（多请求几次）。分开击破，各 30 秒。

## 复盘

- 解题路径：识别 JS 刷新 → 禁用 JavaScript → 手动刷新等熊猫 → Ctrl+U 搜 flag，全程 3 分钟
- **第一次使用 DevTools 命令菜单**（`Ctrl+Shift+P`）——里面还藏着 dozens of 好东西（截图全页、阻塞请求、覆盖 CSS），值得把玩
- **第一次接触"重放"思维**——HTTP 无状态，请求可以无限重发，服务器每次独立响应。重放攻击（Replay Attack）在真实世界对应：短信验证码重放、支付请求重放，防御手段是 nonce / 时间戳 / 一次性 token
- 知识链更新：滑稽（**看**源码）→ 计算器（**改**前端）→ alert（**解**编码）→ GET/POST（**构造**请求）→ 头等舱（**查**响应头）→ 本题（**禁 JS + 重放**）
- 同类题识别：页面强制跳转/刷新/弹窗 = 先禁 JS；题目说"多试几次/随机/速度" = 上重放或脚本
