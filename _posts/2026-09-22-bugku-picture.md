## 题目描述

这是一张单纯的图片。

## 解题过程

### 0x01 下载图片

打开环境，页面上就是一张图片。"单纯"两个字反而可疑——**强调单纯 = 提示不单纯**，CTF 出题人的经典反向操作。

右键图片 → **「图片另存为」**，保存到本地（如 `1.jpg`）。

### 0x02 用记事本直接打开图片

图片本质是**二进制文件**，但 flag 通常以**明文文本**形式藏在里面。最零门槛的查看方式：

1. 右键图片文件 → **「打开方式」** → 选择 **「记事本」**
2. 会看到满屏乱码（正常，那是图片的二进制数据以文本形式显示）
3. `Ctrl + F` 搜索 `flag`（或 `KEY`、`BUGKU`）
4. 在文件**末尾附近**找到：

```text
flag{***}
```


### 0x03 拿分

复制提交，+10 分。

### 备选姿势

- **010 Editor / HxD**（十六进制编辑器）：更专业的二进制查看，`Ctrl+F` 搜文本
- **F12 网络面板**：点开图片请求，看**响应原文**——和记事本等效，连下载都省了
- **Linux/Mac 命令行**：`strings 1.jpg | grep -i flag`，提取文件中所有可打印字符串

## 原理分析

### 图片文件的"加料"空间

JPEG / PNG / GIF 都有明确的**文件结构**：解析器从头读，读到**结束标记**（如 JPEG 的 `FFD9`）就停止工作。**结束标记之后的数据，图片查看器直接无视——但文件里确实存在**。

于是产生了最简单的隐写方式：**尾部附加**——把一段文本（flag、压缩包、一句话）直接拼接在合法图片末尾：

```
[正常图片数据 FF D0 FF D9 结束标记] [附加的 flag 文本]
                ↑                        ↑
          查看器读到这里就停        记事本/strings 能看到
```

图片显示完全正常，肉眼零异常——这就是"单纯的图片"不单纯的地方。

### 隐写家族地图

尾部附加只是文件隐写的入门款，这一族还包括：

| 手法 | 说明 | 常用工具 |
|------|------|---------|
| 尾部附加 | 结束标记后拼数据 | 记事本、`strings`、binwalk |
| 修改宽高 | 改图片头部的尺寸字段，把下半截"藏起来" | 010 Editor、stegsolve |
| LSB 隐写 | 改像素最低位，肉眼不可见 | stegsolve、zsteg、Python(PIL) |
| 文件头伪造 | 改 magic 前缀伪装文件类型 | 010 Editor |

**标准排查顺序**：先看尾部（本题）→ 再查文件头和宽高 → 最后上 stegsolve 查 LSB。

## 复盘

- 解题路径：另存图片 → 记事本打开 → 搜 flag → 提交，全程 2 分钟
- **新工具认知**：记事本能打开"不是文本的文件"——二进制文件里搜字符串是 MISC 的基本功；Linux 的 `strings` 命令是它的专业版
- **出题人语言解读**：题目说"单纯"，反而不单纯；题面与实际不符时，永远是**文件/流量/数据本身**说了算
- 知识链更新：WEB 七题（看/改/解/构造/重放）→ MISC 第一题开启**文件层**视角：数据不止有"页面"这一种载体
- 同类题识别：给文件（图片/音频/压缩包）的题，第一步永远是**用十六进制/文本方式看一遍首尾**
