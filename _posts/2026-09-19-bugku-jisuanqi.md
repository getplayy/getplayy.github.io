## 题目描述

一道计算题，输入答案验证即可。

## 解题过程

### 0x01 侦察页面

打开环境，页面是一道两位数加法（数字随机，例如 `15 + 16 = ?`），下方一个输入框加"验证"按钮。

尝试输入答案时发现问题：**输入框只能敲进 1 个数字**——两位数的答案根本填不进去。

### 0x02 定位限制来源

`F12` 打开开发者工具，用元素选择器（`Ctrl + Shift + C`）点击输入框，Elements 面板定位到：

```html
<input class="input" maxlength="1" type="text">
```

限制来自 `maxlength="1"`——一个**纯前端**的 HTML 属性。

### 0x03 修改属性并提交

双击 `maxlength="1"`，将值改为 `"999"`（或右键删除该属性），页面无需刷新：

*（此处配一张修改前后的 Elements 对比截图）*

回到输入框，完整输入答案，点击验证，拿到 flag：

```text
flag{***}
```

提交平台，+10 分。

## 原理分析

### 前端校验为什么不可信

`maxlength` 属于浏览器本地执行的约束，和 JS 表单校验、禁用的按钮、隐藏的 `input` 一样，**全部只运行在客户端**。客户端对用户是完全开放的：

- F12 可以随意增删改 DOM 属性
- Burp Suite 可以在请求发出前拦截并修改任意参数
- `curl` / Python 脚本可以完全无视页面、直接构造 HTTP 请求

本题的服务端拿到答案后没有做长度或格式的二次校验，"信任"了前端传来的数据，于是前端这道纸糊的门被推开就直接通关。

### 安全启示

Web 安全的黄金法则：**前端校验只能用于体验优化（即时提示），真正的防线必须建在服务端**。凡是重要逻辑——长度、格式、权限、价格——服务端都必须重新验证一遍。

真实攻击场景对应：

| 前端手段 | 攻击者绕过方式 |
|----------|----------------|
| `maxlength` 限制长度 | 改 DOM / 改包 |
| JS 禁用提交按钮 | 删除 disabled 属性 / 直接发请求 |
| 隐藏字段携带价格、折扣 | 改包修改隐藏字段值 |
| 前端 JS 判断用户身份 | 跳过页面直接调接口 |

## 复盘

- 解题路径：输入受限 → 元素定位 → 发现 `maxlength="1"` → 改大 → 输入提交，1 分钟内完成
- **本题其实不止一种解法**，改 `maxlength` 只是最快的一种，另外两种更值得练习：
  1. **Burp 改包**：随便输 1 位数字点验证，用 Burp 拦截请求，把答案参数改成正确值再放行——顺便熟悉 Burp 的基本操作（后面「你必须让他停下」会用到）
  2. **脚本提交**：观察验证请求的参数名，用 Python `requests` 直接 POST 正确答案——练习"脱离页面直接与接口对话"的思路
- 同类题识别：**凡是"不让你输入/不让你点"的限制，默认都是前端限制，先 F12 看属性、再考虑绕过页面直接发请求**
- 陷阱提醒：改完 `maxlength` 不要刷新页面——刷新会把 DOM 恢复原状，需要重新修改
