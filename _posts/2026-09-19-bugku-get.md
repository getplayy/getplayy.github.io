## 题目描述

页面直接给出一段 PHP 源码。

## 解题过程

### 0x01 审计源码

打开环境，页面上是一段 PHP 代码——这是第一次遇到**代码审计**类题型，先把代码逐行读懂：

```php
$what = $_GET['what'];
echo $what;
if ($what == 'flag')
    echo 'flag{***}';
```

逻辑翻译：接收 GET 方式传入的参数 `what` 并回显；当它的值等于字符串 `flag` 时，输出 flag。**通关条件直接写在脸上了**——满足它即可。

### 0x02 构造 GET 请求

GET 传参的语法：URL 后以 `?` 开始，`参数名=值`，多个参数用 `&` 连接。在地址栏直接追加：

```text
http://题目地址/?what=flag
```

回车，页面回显 `flag{***}`。



### 0x03 拿分

复制 flag 提交平台，+10 分。

## 原理分析

### GET：HTTP 最基本的传参方式

HTTP 请求携带参数的两种经典方式：

| | GET | POST |
|---|---|---|
| 参数位置 | URL 中（`?key=value&key2=value2`） | 请求体（body）中 |
| 肉眼可见 | 地址栏直接可见 | 需抓包或工具 |
| 地址栏能直接发 | ✅ | ❌ |
| 典型用途 | 查询、分页、分享链接 | 登录表单、文件上传 |

PHP 用超全局变量 `$_GET` / `$_POST` 分别接收两种方式的参数。

### 页面只是构造请求的途径之一

本题的关键认知：服务器只认"收到 `what=flag` 的 GET 请求"，至于这个请求是**页面表单、地址栏手敲、Hackbar、curl 还是 Python 脚本**发出的，它一概不知、也不关心。地址栏能解，等价地：

```bash
curl "http://题目地址/?what=flag"
```

```python
import requests
print(requests.get('http://题目地址', params={'what': 'flag'}).text)
```

这正是「计算器」一题"客户端不可信"原理的正面应用：**参数就是参数，谁来构造都行**。

### 代码审计入门

给源码的题，解法永远藏在条件里：`if` 判断什么、过滤什么、包含什么。本题只有一个等值判断，是审计题的最简形态；后续题目过滤逻辑会越来越复杂（如「矛盾」考 PHP 弱类型比较的绕过）。

## 复盘

- 解题路径：读代码 → 找到条件 `what == 'flag'` → URL 传参 → 提交，全程 1 分钟
- **GET 语法细节**：`?` 只出现一次（第一个参数前），后续参数用 `&`；参数值里的空格、`&`、`#` 等特殊字符需 URL 编码（空格 → `%20`）
- **渗透视角**：真实场景中 GET 参数是最常见的注入点——搜索框的 `?q=`、文章页的 `?id=1`，手工改参数是测试任何 Web 应用的第一步
- 知识链回顾：滑稽（**看**源码）→ 计算器（**改**前端）→ alert（**解**编码）→ GET/POST（**构造**请求）——四道题串起前端交互的完整攻防视角
- 下一题 POST：同样的代码，参数换到请求体里，正好练习"脱离页面直接发请求"
