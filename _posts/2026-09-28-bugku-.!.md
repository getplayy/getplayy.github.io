## 题目描述

题目名就叫《.!?》，Crypto 方向 20 分，附件是一个 txt 文件。

## 解题过程

### 0x01 打开附件：只有三个符号的世界

解压附件打开 txt，满屏望去**只有 `.` `!` `?` 三个字符**，密密麻麻几百个，没有任何字母数字：

```text
.....!?.?!!....?..?....!........?....!.?!!?.....!?!!.....?....!!?..（节选示意）
```

题目名《.!?》直接剧透了字符集——出题人已经把第一层提示放在标题里了。

### 0x02 识别编码：搜它

做编码题的第一反应永远是**看字符集、搜特征**。三个标点符号组成的密文，拿特征词组合一搜（如 `.!? 密码 crypto` / `ook cipher`）：

> **Ook! 编码**——Brainfuck 语言的"猩猩皮"变体，密文只由 `.` `!` `?` 三个字符组成，两两一组表示指令。

字符集完全吻合，就是它。

### 0x03 在线解码

Ook! 是老牌 esolang（深奥编程语言），在线解码器很多，任选其一：

- [splitbrain.org/services/ook](https://www.splitbrain.org/services/ook) —— 把密文粘进输入框，解出明文
- [tool.bugku.com/brainfuck](https://tool.bugku.com/brainfuck/) —— Bugku 自家工具，选 Ook 模式

把附件全文粘贴进去，输出：

```text
flag{***}
```

*（此处配一张在线解码器输入密文、输出 flag 的截图）*

### 0x04 拿分

复制 flag 提交平台，+20 分。

## 原理分析

### Ook! 的身世：一只只会说 Ook 的猩猩

Ook! 由 David Morgan-Mar 于 2001 年设计，恶搞自 Terry Pratchett 的《碟形世界》系列——书里的图书馆管理员是一只猩猩，它的全部台词只有一个词："Ook"。所以这门语言所有指令都以 `Ook` 开头，靠后面的标点（`Ook.` `Ook!` `Ook?`）排列组合出语义。

### 本体是 Brainfuck：八指令的图灵完备语言

Brainfuck（1993，Urban Müller 设计）是极简编程语言的鼻祖：**只有 8 个字符、一条纸带、一个指针**，却是图灵完备的。八指令：

| 指令 | 含义 | 指令 | 含义 |
|---|---|---|---|
| `>` | 指针右移一格 | `.` | 输出当前格字符 |
| `<` | 指针左移一格 | `,` | 输入一个字符 |
| `+` | 当前格 +1 | `[` | 当前格为 0 则跳到匹配 `]` |
| `-` | 当前格 -1 | `]` | 当前格非 0 则跳回匹配 `[` |

Ook! 只是给这 8 个指令换了套皮——每个指令对应一个"Ook 词组"（如 `Ook. Ook?` = `>`）。而本题密文是**Short Ook!** 形态：连 `Ook` 都省了，直接留标点，两两一组：

| 密文 token | BF 指令 | 密文 token | BF 指令 |
|---|---|---|---|
| `.?` | `>` | `!!` | `.` |
| `?.` | `<` | `!.` | `,` |
| `..` | `+` | `!?` | `[` |
| `.!` | `-` | `?!` | `]` |

### 解码的本质：token 替换 + 解释执行

所谓"解码器"干两件事：① 按 8 组 token 查表替换，还原成 Brainfuck 代码；② 跑一个 BF 解释器执行。第一步 20 行 Python 就能写：

```python
BF = {'.?':'>', '?.':'<', '..':'+', '.!':'-',
      '!!':'.', '!.':',', '!?':'[', '?!':']'}

def short_ook_to_bf(cipher):
    tokens = ''.join(c for c in cipher if c in '.!?')
    return ''.join(BF[tokens[i:i+2]] for i in range(0, len(tokens), 2))
```

我拿这映射做了个闭环实测：把 `flag{...}` 逐字符转成 Brainfuck 代码、再转成 Ook 密文、再解回来——往返一致，映射表无误。所以只要字符集是 `.!?` 且长度为偶数，这个套路必然能解。

### 为什么 CTF 爱考它

字符集小到只剩 3 个符号，肉眼完全不可读，"看起来像乱码"的心理压力拉满；但对工具来说一秒还原。**考点不在解码难度，在认不认识它**——这正是《富强民主》篇"魔改字符集"思想的极致版：那题换成了 12 个中文词，这题直接砍到 3 个标点。

## 复盘

- 解题路径：看字符集（3 符号）→ 搜特征定位 Ook! → 在线解码 → 提交，全程 5 分钟
- **编码识别三板斧**（从散乱的密文一路沉淀下来的方法论）：① 数字符集——3 符号？26 字母？12 中文词？→ 直接圈定候选编码；② 看结构——分组规律、重复模式、长度奇偶；③ 拿特征搜索验证。其中第一步是万能起手式
- **Brainfuck 家族图谱**：见到 `+-<>[].,` 八字符组合是 Brainfuck 本体；全是 `Ook` 是 Ook! 原版；只剩 `.!?` 是 Short Ook!——一家人，认出一个等于认识全家
- 这题标题《.!?》就是提示，呼应 Linux2 的教训：**题目给的每个字都是信息**，格式提示、标题、文件名都可能是钥匙
- 知识链回顾：滑稽（看源码）→ 计算器（改前端）→ alert（解编码）→ GET/POST（构造请求）→ 散乱的密文（换位置）→ 富强民主（换字符集）→ linux/Linux2（捞字符串）→ **.!?（极简字符集）**——编码题的三种形态（位置重排 / 字符集替换 / 极简语言）已集齐
